## 1. Executive Summary

- **Project:** MLX-SAGE (Python package `nex-cli` 0.3.0; import package `nex`)
- **Purpose:** Personal sage partner on Apple Silicon — local MLX dialogue + living direction, hive co-goals with joint beneficence, and optional Superintendant rails (Sentinel policy + propellant-capped Grok + WattOS).
- **Maturity:** **Alpha / advanced prototype** — multiple live surfaces, real tests, not release-hardened.
- **Scale:** ~83 tracked files · ~8.4k lines Python (package+tests) · primary language Python 3.11+
- **Health:** 🟡 — core logic and unit tests green (22/22); no CI, no LICENSE file, dual product identity (Nex multi-model vs Sage destination), incomplete media placeholders, partial TUI approval wiring.
- **Velocity:** Active (12 commits; bulk 2026-06-10, product pivot commit 2026-08-05 `bec3896`).
- **Top strengths:** (1) Real joint-beneficence + hive + sage partner with FS persistence and tests; (2) Superintendant/WattOS/propellant with real demos and honesty about n/a local tokens; (3) Broad Typer surface (chat/agent/serve/mcp/sage/we/supervise) on one package.
- **Top risks:** (1) Product/docs identity split (README = Sage; pyproject = OptiQ multi-model Nex); (2) Quality gates missing (no CI/lint/typecheck; LICENSE absent); (3) Some UI paths construct illustrative PendingApproval with synthetic decision objects (`nex/tui.py`).
- **Verdict:** Ready for **local developer use and continued Stage 2–3 build**; needs honesty pass + CI/LICENSE + forensics on demo-vs-live before release claims.

## 4. Design & Architecture

### 4a. High-level

```
User
 ├─ nex sage tui/dialog     → local MLX (Engine) + SageProfile FS
 ├─ nex we *                → HiveCell + evaluate_joint_beneficence + receipt
 ├─ nex chat/ask/agent/tui  → Engine + ChatSession + tools/sandbox
 ├─ nex serve               → FastAPI OpenAI-compat (/v1/*)
 ├─ nex mcp                 → MCP tools over Engine
 └─ nex supervise / grok-*  → PTY + SentinelPolicy + Enforcer + Propellant + WattOS
                                    └─ optional XAI_API_KEY Grok escalate
```

### 4c. Patterns

- **Registry + profile resolution** (`models.py`, `_resolve_model`)
- **Dataclass reports** (`SessionOversight`, `WattOSReport`, `JointBeneficenceResult`)
- **FS-as-DB** for sage profiles / hive sessions under `sessions/`
- **PTY wrap** for external agents (`pty_runner`, `superintend`)
- **Deterministic policy before LLM** (`SentinelPolicy` → optional Grok)
- **Optional extras** via `pyproject` (`tui`, `server`, `rag`)

### 4d. Primary data flows

1. **Sage chat:** user text → `SageDialog` / profile memory → `Engine` generate → `chat.jsonl`
2. **Hive:** co-goal + roles → `evaluate_joint_beneficence` gate → JSON receipt on disk
3. **Agent:** goal → tool loop in `sandbox/` → optional GROK_IN_LOOP → oversight panel
4. **Supervise:** child argv under PTY → policy/effects → propellant gate → WattOS finally

### 4e. Open design decisions

| Decision | Context | Current default |
|----------|---------|-----------------|
| Product name packaging | MLX-SAGE vs nex-cli | README Sage; package `nex-cli` |
| Full TUI approval vs CLI prints | human-in-loop during supervise | CLI prints + partial TUI queue |
| Live Grok V8 verification | needs API key | Skipped in PROGRESS when no key |
| WattOS on native `nex agent` | unify end report | Oversight report exists; not fully WattOS-unified |
